# The portfolio

Two decks, generated from two scripts. Close a pptx in PowerPoint before
regenerating it or the write fails with EBUSY.

`ai_bin.js` generates `AI_Smart_Bin.pptx`. **This PowerPoint is the assessed
work.** Everything the course marks lives here, not in the markdown files.

```
cd portfolio
bun run ai_bin.js
```

`hardware_log.js` generates `Hardware_Development_Log.pptx`, the dated record of
the mechanical build for someone who wants to see the work rather than the
result. Separate from the assessed deck on purpose, because that one has been
submitted and adding a build-log section to it was tried and reverted.

```
cd portfolio
bun run hardware_log.js
```

Its last two slides are read out of `git log` at generate time, so the dates
cannot drift. Everything else in it is a summary of facts that live in
`docs/`, so if a number changes there, change it in the script too.

| Path | |
| :--- | :--- |
| `ai_bin.js` | The assessed deck. Edit this, never the pptx |
| `hardware_log.js` | The hardware development log deck |
| `images/cad/` | Renders out of the Fusion assembly |
| `images/cad/evolution/` | Design-evolution renders, generated by [`cad/renders/`](../cad/renders/README.md). Do not edit by hand |
| `images/photos/` | Photographs of the real build. Evidence, so take them at the time |
| `images/hardware/` | Supplier pictures of bought parts. Not evidence of anything |
| `images/diagrams/` | Wiring, DIP switch settings, Gantt chart |
| `images/sketches/` | The hand-drawn design options and their source scan |
| `images/screens/` | Screenshots of the dashboard |
| `old/` | Previous versions, kept for reference |
| `feedback/` | Mr Degraeve's marked feedback |

Put a new image in the folder that matches what it **is**, not what slide it
happens to be on. The split that matters is `photos/` against `hardware/`: one
is proof you built something, the other is a picture off a shop listing.

## Before changing a slide

**The current deck has already been submitted.** Ask Sonny before restructuring
or rewriting existing slides. Adding new ones for work done since is the normal
case and is what he expects.

The remaining job is building the physical thing and recording that progress,
which then gets folded back into these slides. Take the facts from
[`docs/build_log.md`](../docs/build_log.md), which is the only place that says
what actually exists.

## Teacher feedback that still applies

- **Criterion 1 must not contain design decisions.** Those belong in Criterion
  2. Keep C1 to the problem, the context and the constraints.
- **Back claims with data and references.** A number with a source beats an
  assertion.
- **Explain the opportunity**, not just the product.

## House style

Match what is already there: the `C.*` colour constants, the `addHeader` and
`addFooter` helpers, Calibri, and the existing font sizes. Write the way Sonny
writes, first person and plain, not like a brochure. No em dashes and no emoji.

Real numbers only. If a figure has not been measured yet, say it has not been
measured. An examiner will ask.
